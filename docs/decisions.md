## ADR-003: Multi-Agent Workflow Management via LangGraph

### Context
The multi-agent system requires strict state management, cyclic execution loops (e.g., Developer ↔ Tester feedback loops), and deterministic conditional branching (e.g., maximum iteration limits).

### Decision
We select **LangGraph** as the multi-agent orchestration framework.

### Justification
1. **Stateful Graph Execution:** Allows passing a centralized `AgentState` across nodes cleanly.
2. **Cyclic Workflows:** Enables conditional loops where code can be tested, reviewed, and routed back to the Developer agent upon failure until `is_approved == True` or `iterations >= MAX_ITERATIONS`.
3. **Observability Integration:** Integrates natively with Langfuse tracing handlers.

## ADR-004: Code Execution Sandbox Isolation

### Context
Executing untrusted code generated by an LLM on the host machine presents severe security risks.

### Decision
We implement a dedicated, isolated **Docker-based Executor service**.

### Justification
1. **Security Policy Enforcement (SOUL):** Prevents generated code from accessing the host filesystem, environment secrets, or network resources.
2. **Deterministic Test Execution:** Code and tests run in a predictable, clean Python environment returning standardized JSON payloads (`stdout`, `stderr`, `exit_code`).

## ADR-005: Persistent Memory Strategy (SQLite)

### Context
The system needs to store interaction history and past successful solutions to inform future agent planning without relying solely on ephemeral context windows.

### Decision
We implement a relational persistent memory store using **SQLite** (`agent_memory.db`), separated from the static technical knowledge base (`knowledge/`).

### Justification
1. **Relational Traceability:** Plain vector RAG is insufficient to represent full agent task cycles and status flags (`is_approved`).
2. **Simplicity & Zero Infrastructure:** Fits the MVP requirements without external database overhead while providing exact structured retrieval of past coding solutions.

## ADR-006: Observability via Langfuse

### Context
Multi-agent interactions can become opaque, making it difficult to analyze token usage, node latency, and failure points in LLM calls.

### Decision
We integrate **Langfuse** tracing at the Orchestrator level via `CallbackHandler`.

### Justification
1. **Full Trace Visibility:** Captures end-to-end execution trees from Gateway down to individual LLM node invocations.
2. **Performance Optimization:** Provides clear metrics on latency bottlenecks and agent prompt performance across iterations.
